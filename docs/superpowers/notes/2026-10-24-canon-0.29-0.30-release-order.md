# Canon 0.29 / 0.30 release order

Mirrors lute's 0.49 / 0.50 split (`journeyWorker/lute`,
`docs/superpowers/notes/2026-10-23-lute-0.49-dogfood-triage.md`): first the
release that rewrites the costly structure, with the coding-rules note
binding new code; then one behaviour-preserving sweep of everything else.

Lower-severity copies ride along where they sit in touched code:
`canon-store/src/git_tier.rs:182` returns a deep clone of the cached kind
(cache `Arc` instead), `staleness.rs:156` clones a `HashSet` on every cache
hit, `trust.rs:116-127` re-reads reviews already in the context.

Acceptance (the lute #173 shape):

- A synthetic corpus generator (subjects S, scenarios per subject, evidence
  and reviews per scenario, batch size B) and a release-build bench for
  `canon gate check`, `canon status` and `canon evidence add` batches.
- The bench gate checks **growth shape**: at 10× scenarios, CPU and peak RSS
  grow by about 10×, not 100×; at 10× batch size with a fixed ledger, batch
  landing grows by about 10×, not by ledger × batch.
- Output is byte-identical: `canon gate check --json`, `canon status --json`
  and the conformance cases do not change.
- New code follows `docs/design/rust-coding-rules.md` if it is `Accepted`
  when a slice starts. Existing code is not swept.

## 0.30 — coding-rules sweep

`docs/design/rust-coding-rules.md` §9: lints into CI (a new pinned `clippy`
job), visibility, error types, panics. Behaviour-preserving; runs with no
other branch open.

## Why this order

0.29 rewrites the derivation layer of `canon-gate` and the gate/status half
of `canon-cli`, which together hold most of the sweep's sites (`canon-cli`
alone has 748 of 1,113). Sweeping first would polish code about to be
replaced, and the sweep is safer on top of 0.29's bench and byte-identity
checks.
