## Principle

A brief is the one document a human reads before canon lets work start. It
says what changes for the user, in the language it is written in, and in
plain sentences. A rule can count citations, asides, dates and endings
without judgment. Those counts are what an agent fixes before it asks the
human, and what the human sees next to the brief.

## Decisions

- **D1: language by detection.**
  - Each brief is judged in the language its text is written in. The script of its prose letters decides: Hangul is `ko`, and Latin is `en`. Other CJK scripts are detected and named, but canon ships no rule list for them, so only the structure rules apply. Code spans, fenced code, comments and markers are not counted.
  - A section whose script differs from the brief's is judged in its own language.
  - `language:` in `canon.yaml` is an override, not a precondition: when set, it decides.
  - `brief check` (text and JSON) names the language it used and its source, `detected` or `configured`. When the configured and detected languages differ, it says so in one line.
  - `canon status`, the guards and the dashboard use the same resolution, through one function.
- **D2: context sections are judged too.** Intent and Questions get the style rules: evaluative, connective, contrast, colloquial and degree, plus the new rules of D3. Length and key-sentence rules stay on normative sections.
- **D3: new prose rules.** Each rule is deterministic, advisory and waivable, and covers one mechanism. Each applies to `ko` and `en`, and each finding carries the matched text or the measured value.
  - `prose.code-citation`: `path:line`, file paths, and identifiers in backticks inside sentences. Provenance goes on one `Source:` line, which is exempt.
  - `prose.parenthetical`: parenthetical asides above a per-section density.
  - `prose.decision-history`: dates and "decided / changed on …" notes in normative or Intent text.
  - `prose.ai-vocabulary`: a short closed list of metaphors and stock AI words. Start small and deterministic.
  - `prose.ko-ending`: Korean sentences that do not end in the plain declarative `~다`. This covers polite and colloquial endings and imperative or hortative ones. Flow steps and list fragments are exempt.
  - `prose.length`: a character budget per section and for the whole brief. The finding states the measured value and the budget.
  - Thresholds are calibrated on fixtures written in the style of the 14 measured briefs, which must report findings for each mechanism. They are also calibrated on canon's own earlier briefs (conformance fixtures and the eval 13 fixture briefs) and on good Korean fixtures, which must stay free of the new rules.
- **D4: polish before the human stop.**
  - When a brief has no blockers and prose advisories remain, `canon status` and `meta.next` name the polish pass (`reference/brief-polish.md`, then `canon brief check`) as the planner's step, before the human step. It never blocks: approving a brief with advisories still works.
  - The briefs page shows each brief's advisory count and its findings grouped by rule, and a total.
- **D5: skill text.**
  - Rewrite `reference/brief-polish.md`. Choose the document mode first, then apply the rule ids and how to fix each one: current behavior versus desired behavior, interfaces described by behavior, and acceptance a reader can verify alone. Keep a single source of truth and leave no paths or line numbers.
  - Add a compression pass to `role-planner.md`. In each paragraph, keep only the sentences that state a condition, an action, a result or a number. Turn a run of three or more items into a list or a table.
  - Assumptions and a Not Doing list go into their existing sections.
  - Clean-room: the vendor skill packs in `docs/research/vendor-audits/` are read for ideas; canon's text is its own.
- **D6: reported issues.**
  - #104: an `evidence add` (and every command taking `--project-id` with `--scenario-id`) whose `--project-id` names no configured spec root is refused before anything is written. The hint lists the configured roots.
  - #105 and #107: `canon init` and `canon migrate` add `.canon/dashboard-snapshot/`, `.canon/learn/` and `.canon/r2/` to the managed ignore lines. `canon skills doctor` and `canon init --check-config` mention a missing entry. After `canon dashboard` in a freshly initialized repo, `git status` is clean.
- **D7: acceptance.**
  - (a) Workspace tests pass.
  - (b) Canon's own gate is clean, with new scenarios evidenced and independently reviewed by a separate process.
  - (c) Dogfood eval 14. A consumer repo copy has no `language:` set. A planner agent writes three or more Korean briefs. `brief check` detects `ko` and reports findings, and the agent runs the polish pass before it stops for the human. The final briefs are measured against the before numbers (length, citations, parentheticals, advisories), and the eval record holds the before and after brief text. It also holds screenshots of the briefs page showing advisories.
