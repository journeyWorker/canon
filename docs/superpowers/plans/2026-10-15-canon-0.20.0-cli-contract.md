## Why

Issue #53, from `docs/research/deep-research-report.md`: an agent spends its calls on discovery and recovery (wrong command → `--help` → parse prose → retry), not on typing. canon is driven by agents, so its CLI is their interface. An inventory of 0.19's surface (`crates/canon-cli/src/main.rs:51-1427`, dispatch `:1429-1732`) against the report's checklist:

| Checklist item | 0.19 | Evidence |
|---|---|---|
| Discovery without reading help | `canon context --json` describes record kinds and fields, not commands | `context.rs:61-85` |
| `--json` on every command | Missing on `init`, `migrate`, `format`, `feature new`, `scenario new`, `change new`, `inventory sync`, `plugin sync`, `skills *`, `tier age`, `report`, `dashboard`, `gate check` | inventory |
| JSON-only stdout in JSON mode | Mostly (advisories go to stderr) | `main.rs:1849-1930`, `retrieve.rs:316-323` |
| Stable string error codes | Only `canon brief` / `brief approve` (0.19) emit `{"error":{code,message}}`; everything else is free text on stderr | `brief_check.rs:1089`, `brief_approve.rs:58` |
| Exit codes documented | 0/1/2 by convention, per-module exceptions (`context` always 0, `dispatch diff` 0, `evidence vault` 0 on partial) | inventory |
| Bounded lists | No `--limit`/`--cursor`; `query`, `finding list`, `divergence status`, `export` return everything | `query.rs`, `main.rs:314-345` |
| Field projection | None | — |
| One canonical verb per meaning | `learn request` duplicates `learn approve` (same implementation) | `main.rs:569-593`, `learn.rs:267-269` |
| Risky writes need a plan digest | `purge` has `--dry-run` but no confirm-by-digest | `retention.rs:202-214` |
| Unknown flags fail fast | Yes (clap derive, no `allow_unknown_args`) | `main.rs:48-51` |
| No prompt in agent use | `init` prompts only on a TTY without `--providers` | `init.rs:373-377` |

## Decisions

- **D1: `canon schema` (discovery).** `canon schema [<command path>…] [--json]`, generated from the clap command tree plus one metadata table: for each leaf command its canonical path, effect (`read|write|destructive`), arguments and options (name, type, required, enum values, default, repeatable), whether it supports `--json`, its exit codes and the error codes it can emit. Bare `canon schema` lists command paths only; `canon schema evidence add` returns one command. No repo access, no network. A test fails when a leaf command has no metadata row, so the table cannot drift from clap.
- **D2: `--json` everywhere, JSON-only stdout.** Every leaf command accepts `--json`. In JSON mode stdout carries exactly one JSON document (or NDJSON where D4 says so); progress, refresh notices and advisories go to stderr. Existing JSON shapes keep their fields (`status` keeps `statusVersion: 3`); commands that gain JSON get `{ "data": …, "meta": { "command": "<path>" } }`.
- **D3: one error contract.** A shared `CliError { code, message, hint, retryable, exit }` in canon-cli. Every refusal and operational error has a stable SCREAMING_SNAKE `code` (e.g. `BRIEF_CHANGED_SINCE_APPROVAL`, `UNCOVERED_SCENARIO`, `CHANGE_AMBIGUOUS`, `CONFIG_UNREADABLE`). Human mode prints `canon <path>: <CODE> — <message>` plus `hint:` on stderr; JSON mode prints `{"error":{code,message,hint,retryable}}` on stdout. Exit codes stay as they are in 0.19 (0 ok, 1 gate/operational failure, 2 refusal or usage), so CI that reads exit codes keeps working; the code is the precise contract. Clap usage errors keep exit 2 and gain code `USAGE` in JSON mode.
- **D4: bounded collections and projection.** `query`, `finding list`, `divergence status`, `export` take `--limit <n>` (default 100), `--cursor <opaque>` and `--all`; the JSON result's `meta` carries `returned`, `hasMore`, `nextCursor`. Human mode prints a last line naming the next cursor when more remain. `--fields a,b,c` projects records in `query` and `finding list`; an unknown field is `UNKNOWN_FIELD`. `query --json` with no `--limit` changes from "everything" to the first 100: noted in Migration.
- **D5: plan and confirm for destructive writes.** `canon purge --plan` prints the records it would remove and a digest of that plan; `canon purge --confirm <digest>` removes only if the current plan has the same digest, else `PLAN_CHANGED`. `--dry-run` becomes `--plan` (clean cutover). The schema marks `purge` destructive.
- **D6: one name per meaning.** Remove `learn request` (duplicate of `learn approve`). `fmt` stays a clap alias of `format` but `schema` and errors name `format`. No other renames in 0.20: renaming resource/verb pairs breaks every skill and script for little gain; `schema` makes the existing names discoverable.
- **D7: skill.** The skill tells agents to start from `canon schema <command> --json` when unsure of a command, to pass `--json` and read `error.code`, and to page with `--cursor`. The AGENTS block gains one line.
- **D8: acceptance.**
  - (a) Contract tests (integration, no LLM): every leaf command in `schema` runs with `--json` and its stdout parses as JSON (success or error); every non-zero exit in JSON mode carries an `error.code`; `query --limit 2` pages with `nextCursor` to the same set `--all` returns; `purge --confirm` with a stale digest refuses.
  - (b) Dogfood eval 8 on omp (copy of `nyan-omp-020`, a new small feature): `trace_check` reports first-command validity and recovery depth; compare with eval 7 (calls per success, recovery depth). Pass: no regression in calls per success, every recovery after a canon error is one call.
