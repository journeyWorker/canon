## Principle

`GateContext::load` reads each record kind once per command. Everything a
command derives from a whole kind (latest-by-key folds, indexes by subject,
scenario and change, the archive, the code tree, the vocabulary snapshot) is
derived once per command too, and per-item questions are lookups into it.
Output does not change: this release changes cost, not behaviour.

## Why (measured)

Own corpus at 0642815c, release build, best of 3: `canon gate check` 1.32 s
CPU / 37 MB peak RSS, `canon status` 1.46 s / 36 MB (24 subjects, about 600
scenarios, 853 evidence records, 931 reviews). The growth with corpus size is
in the release-order note's table (10 findings, read from the code). D1 adds
the measurement that the table lacks.

## Decisions

- **D1: synthetic corpus bench.** `scripts/bench/gen_corpus.py` writes a repo
  with S subjects, Sc scenarios per subject, E evidence and R reviews per
  scenario. `scripts/bench/run.py` builds nothing; it runs a given `canon`
  binary over a grid and reports CPU (user+sys), peak RSS, wall and load per
  point. `scripts/bench/check_shape.py` fails when 10× scenarios costs more
  than a stated factor (default 20×) over 1× in CPU or RSS, and when 10×
  batch size at a fixed ledger costs more than 20× over 1×. A CI job runs a
  small grid with the release binary.
- **D2: gate derivation is computed once** (findings 3–6, plus the trust
  re-read and the staleness clone). Lazy, per-command indexes held by the gate
  context; callers borrow.
- **D3: CLI derivation is computed once** (findings 1, 7, 8, and the flow
  scenario lookup in `status`).
- **D4: batch evidence lands in one promotion** (finding 2), the store cache
  hands out shared values instead of deep clones, policy evaluation compiles
  each program once and does not spawn a thread per record (finding 9), and
  risk shares one staleness result and caches git by sha (finding 10).
- **D5: byte identity.** `canon gate check --json`, `canon status --json` on
  canon's own corpus and on the synthetic corpus, and the conformance cases,
  are byte-identical to 0.28.0.
- **D6: acceptance.** (a) Workspace tests pass. (b) D5 holds. (c) The D1
  shape gate passes and the before/after table is in the README release
  section. (d) Canon's own gate is clean.
