# Canon 0.24.0: one name per concept, attachments by test

- **Branch:** `feat/0.24`. Slices on their own branches (`feat/0.24-names`, `feat/0.24-attachments`), merged in order. One PR to `main`.
- **Base:** `main` at d7038dad (0.23.0).
- **Version:** 0.24.0 (minor).
- **Status:** IN PROGRESS.
- **Issues:** #85, #83.

## Principle

An agent learns canon's vocabulary from the command it just ran and applies
it to the next one. A concept spelled two ways makes the second call wrong;
a batch that binds every named file to every scenario makes the evidence
wrong. Both are fixed at the source: one spelling, and the report says which
file belongs to which test.

## Why (measured)

| Finding | Measurement |
|---|---|
| Two spellings per concept (#85) | dogfood evals 7–11 (0.19–0.23): every wrong-shape canon call, 0–3 per run, came from `--change`/`--change-id`, `--project`/`--project-id` or `query --kind` names: `finding list --change`, `scenario new --project-id`, `query --kind review_record` |
| The split (0.23.0 `canon schema --all`) | `--change`: brief approve, brief check, review add, scenario new; `--change-id`: finding add/close/list, query. `--project`: feature new, scenario new; `--project-id`: divergence ×4, evidence add, evidence approval-payload, review add. `--subject`: change new, retrieve, scenario new, subject adopt (no `-id` form). `--actor`: feature new, learn rollback, scenario new; `--actor-id`: 10 commands. Kinds: `evidence_record` is the only `*_record` |
| Batch binds every file to every scenario (#83) | eval 11: both implementers looped `reports/screens/*.png` into `--all-scenarios`; each of 103 records bound ~30 screenshots (avg 32.4 attachments) |

## Decisions

- **D1: one spelling per concept (#85).**
  - Rule: a flag whose value is the id of a record or configured entity is `--<noun>-id`. It is the spelling most commands already use.
  - Renames: `--change` → `--change-id` (brief approve, brief check, review add, scenario new); `--project` → `--project-id` (feature new, scenario new); `--subject` → `--subject-id` (change new, retrieve, scenario new, subject adopt); `--actor` → `--actor-id` (feature new, learn rollback, scenario new).
  - `--kind` values of `query`, `export` and `purge` carry no `_record` suffix: `evidence_record` → `evidence`. The record's own `kind` field, ledger paths and `canon.yaml` routing keys are storage and keep `evidence_record`.
  - Everything canon prints for an agent to type back (hints, `meta.next`, examples, `after_help`, the skill, the website, the AGENTS block) uses the new spellings.
- **D2: deprecation, the 0.21 mechanism, for one minor.**
  - `deprecation.rs` returns, keyed on flags and values instead of command paths. An old spelling still runs, prints `canon <command>: --<old> is deprecated — use --<new> (removed in 0.25.0)` on stderr, and in JSON adds `meta.deprecated: [{"used", "use", "removedIn"}]`.
  - Deprecated values of `--kind`: `evidence_record`, and `<kind>_record` for every other kind (the spelling agents guessed).
  - `canon schema <command>` lists each option's deprecated spellings (`deprecatedAliases`); help does not show them.
  - 0.25.0 removes them; they become usage errors whose hint names the new spelling.
- **D3: the test that keeps it that way.** A contract test walks the whole clap tree and fails when two visible flags differ only by an `-id` suffix, when a concept in the table (change, project, subject, actor, scenario, session) is spelled other than its canonical form, or when a `--kind` value ends in `_record`. The checker is a function over (command, flags), unit-tested against a synthetic split.
- **D4: attachments by test (#83).**
  - A report says which file belongs to which test: JUnit `[[ATTACHMENT|<path>]]` lines in a test case's `<system-out>` (Playwright's JUnit reporter; a relative path resolves against the report's directory) and Cucumber JSON `embeddings` (stored by digest). A record binds the attachments of the cases it owns, in batch and single-scenario mode alike.
  - `evidence add --all-scenarios` refuses a bare `--artifact <path>` (it would bind to every scenario); `--artifact <scenario-id>=<path>` binds one file to one scenario of the batch.
  - A report attachment that is missing or over the size limit is refused, naming the case and the path; nothing is written.
  - Review pins are unchanged: for report evidence they pin the report format and matched case names, so a re-run's new screenshot bytes do not stale a review.
- **D5: acceptance.**
  - (a) Contract tests for D1–D4; conformance cases re-blessed where spellings change, plus one case for a deprecated spelling (stderr line, `meta.deprecated`, still runs).
  - (b) Canon's own repo: new scenarios evidenced and reviewed by an independent session; `canon gate check` clean.
  - (c) Dogfood eval 12 on omp, `language: ko`, orchestrated planner/implementer/reviewer subagents running the 0.24 build: 0 wrong-shape canon calls caused by naming (`evals/dogfood/trace_check.py`), and no screenshot bound to a scenario other than its own.
