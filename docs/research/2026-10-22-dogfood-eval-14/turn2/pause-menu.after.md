# 일시 정지 메뉴 확인 단계

Source: 일시 정지 메뉴와 화면 전환 코드(src/hud/PauseMenu.tsx, src/App.tsx), 입력, 시뮬레이션, 기록 코드(src/engine), 기존 HUD 테스트(tests/hud.test.tsx).

<!-- canon:section intent role=context -->
## 의도

일시 정지 메뉴는 Esc로 열리고 Resume, Restart Level, Quit to Menu 세 버튼을 보여 준다. Restart와 Quit은 확인 없이 바로 실행된다. 잘못 클릭하면 몇 분짜리 run이 통째로 사라지고, 진행 중이던 시간과 acorn은 어디에도 남지 않는다. 두 동작이 run을 잃는 위험은 같다. 메뉴는 마우스 없이는 쓸 수 없다. 이 변경은 메뉴에 키보드 조작과 두 동작의 확인 단계를 더한다.

<!-- canon:section outcome role=normative -->
## 원하는 결과

==**Restart Level과 Quit to Menu는 run을 버리기 전에 한 번 더 확인을 받는다.**== Resume은 확인을 묻지 않는다. 메뉴는 키보드만으로 조작할 수 있다. 키보드 사용자와 마우스 사용자는 같은 확인 단계를 거친다. 메뉴를 열고 닫는 동작은 지금과 같다.

<!-- canon:section flow role=normative -->
## 사용자 흐름

1. F1 플레이어는 진행 중인 레벨을 보고 → Esc를 누르면 → 멈춘 게임 위에 첫 번째 항목에 초점이 놓인 일시 정지 메뉴가 나타난다.
2. F2 플레이어는 일시 정지 메뉴를 보고 → 화살표 키로 이동해 Resume에서 Enter를 누르거나 Esc를 다시 누르면 → 멈췄던 바로 그 자리에서 레벨로 돌아간다.
3. F3 플레이어는 일시 정지 메뉴를 보고 → Restart Level을 고르면 → ==**확인 질문을 받고, 확인하면 같은 레벨의 깨끗한 시작 상태가 된다.**==
4. F4 플레이어는 일시 정지 메뉴를 보고 → Quit to Menu를 고르면 → 확인 질문을 받고, 확인하면 끝내지 못한 run이 버려진 채 레벨 선택 메뉴가 보인다.

## 단계 상세

### F1 메뉴 열기

- Esc는 플레이 중에만 메뉴를 연다. 레벨 완료 화면, 게임 오버, 레벨 선택에서는 무시한다.
- 메뉴가 열려 있는 동안 시뮬레이션과 타이머는 지금처럼 멈춘다.
- 메뉴가 열리면 초점은 Resume에 놓인다.

### F2 이어서 하기

- 위, 아래 화살표로 초점을 옮긴다. 끝에서는 반대쪽 끝으로 돌아간다. Enter는 초점이 놓인 항목을 실행한다.
- 메뉴가 열린 동안 방향키는 메뉴만 조작한다. 게임 입력도 같은 키를 받지만 시뮬레이션이 멈춰 있으므로 플레이어는 움직이지 않는다.
- Resume과 두 번째 Esc는 모두 메뉴를 닫는다. 멈춰 있던 구간은 경과 시간에 들어가지 않으며, 이 동작은 바꾸지 않는다.

### F3 Restart Level

- 선택하면 "Restart this level? Your progress is lost." 문구와 Cancel, Restart 버튼을 보여 준다.
- Cancel은 메뉴로 돌아간다. Restart는 하트, 점수, acorn, 타이머를 초기화한다. 승리 화면에서 R을 눌렀을 때와 같은 결과다.

### F4 Quit to Menu

- 선택하면 "Quit to the menu? Your progress in this level is lost." 문구와 Cancel, Quit 버튼을 보여 준다.
- Quit은 레벨 선택으로 돌아간다. 열린 레벨과 저장된 기록은 그대로 둔다.
- 중단된 run은 best를 기록하지 않는다. 기록은 레벨을 완료했을 때만 저장된다.

F3과 F4의 확인 창에 공통으로 적용한다.

- 확인 창은 일시 정지 메뉴와 같은 overlay 안에서 내용만 바꾼다. 확인 중에도 게임은 멈춰 있다.
- ==**확인 창이 열리면 초점은 Cancel에 놓인다.**== Enter를 연타해도 run이 버려지지 않는다.
- 확인 중인지 여부는 메뉴 쪽 상태로만 두고 시뮬레이션에는 알리지 않는다.
- 레벨 완료나 게임 오버 화면이 떠 있으면 메뉴가 열리지 않으므로, 확인 창이 다른 overlay와 겹치지 않는다.

## 인수 조건

- F1: 플레이 중 Esc를 누르면 Resume에 초점이 놓인 메뉴가 열리고 게임은 멈춘다. 실패 경로: 승리 화면, 게임 오버, 레벨 선택에서 Esc를 눌러도 아무것도 열리지 않는다.
- F2: Resume에서 Enter를 누르거나 Esc를 다시 누르면 멈춘 상태에서 이어진다. 실패 경로: 메뉴가 열린 동안 누르고 있는 이동 키는 플레이어를 움직이지 않는다.
- F3: Restart를 확인하면 깨끗한 레벨이 된다. 실패 경로: ==**Cancel은 run, 점수, acorn을 건드리지 않는다.**==
- F4: Quit을 확인하면 레벨 선택이 보인다. 실패 경로: Cancel은 run을 유지하고, 중단한 run은 저장된 best를 덮어쓰지 않는다.

## 질문과 가정

- 질문: 확인 창 안에서 Esc는 Cancel을 뜻하는가? 그렇다고 가정한다.
- 질문: 일시 정지 키는 Esc뿐인가, P도 되는가? 지금은 P로도 메뉴가 열린다. 이 변경은 두 키를 그대로 둔다고 가정한다.
- 질문: 설정에서 확인을 끌 수 있어야 하는가? 설정 화면이 없으므로 아니라고 가정한다.
- 질문: 확인 창의 초점을 Cancel에 두는 것이 맞는가? 그렇다고 가정한다. Restart나 Quit에 먼저 두면 Enter 연타로 run이 버려진다.
- 질문: 메뉴가 열린 상태에서 R을 누르면 어떻게 되는가? 지금은 R 요청이 쌓여 있다가 메뉴를 닫는 순간 재시작이 실행될 수 있어 확인 단계를 우회한다. 메뉴가 열려 있는 동안 누른 R은 버린다고 가정한다.
- 가정: 확인 문구는 지금의 HUD, 메뉴 문구처럼 영어로 쓰고 번역하지 않는다. 한국어 화면 문구가 필요해지면 별도 변경으로 다룬다.
- 가정: 기존 일시 정지 시나리오 platformer.hud.01은 그대로 두고, 이 변경은 그 위에 시나리오를 더한다.
- 가정: 화살표 이동은 메뉴가 세로 배치라 위, 아래만 지원한다. 확인 창의 두 버튼도 위, 아래로 오간다. 좌우 화살표는 필요해지면 나중에 추가할 수 있다.
- 가정: 확인 창에서 Restart를 고르면 메뉴가 닫히고 일시 정지가 풀린다. 지금의 Restart와 같은 순서라 곧바로 깨끗한 레벨에서 플레이한다.
- 가정: 확인 창에서 Quit을 고르면 메뉴가 닫히고 레벨 선택이 보인다. 시뮬레이션은 멈춘 채 남았다가 다음 레벨을 고를 때 새로 불러오므로, 중단된 run의 상태가 남아도 해가 없다.

## 범위 밖

- 설정, 음량, 키 재설정 화면은 다루지 않는다.
- 브라우저 탭의 초점이 사라질 때 자동으로 일시 정지하는 기능은 다루지 않는다.
- 다음 세션에서 이어 하기 위한 run 저장은 다루지 않는다.
