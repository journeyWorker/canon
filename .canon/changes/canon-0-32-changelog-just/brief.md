# README를 줄이고 CHANGELOG와 justfile 도입

## Intent

README는 4,056줄이고, 그중 약 3,940줄이 0.8.0부터 0.31.0까지의 릴리스 노트다. 맨 앞의 소개와 시작 안내는 80줄 남짓이다. 게다가 이 노트는 변경 이력으로 읽히지 않는다. 변경 slug, 내부 모듈 이름, 리뷰 라운드 경과, 측정 수치, 구현 이유가 섞여 있어서, 사용자는 "무엇이 바뀌었고 올릴 때 무엇을 해야 하는가"를 찾을 수 없다.

개발 명령도 CI 워크플로 여러 곳에 흩어져 있어서 테스트, clippy, 자체 gate, 생성 문서 갱신을 매번 손으로 친다.

이 변경은 세 가지를 한다. README에는 소개와 시작 안내만 남긴다. 변경 이력은 사람이 읽는 CHANGELOG로 새로 쓴다. 반복 명령은 justfile 레시피로 묶는다.

## Category

build

## Invariants

- ==**canon 바이너리의 동작, 출력, 레저는 바뀌지 않는다.**== usage error의 힌트 문구도 그대로다. 바뀌는 것은 문서, 문서를 읽는 테스트와 생성기의 대상 파일, 소스의 문서 주석, 릴리스 안전 검사의 허용 목록, 새 justfile이다.
- README에는 소개, 시작 안내, 안전 경계, 상태, 레이아웃, live tier 환경 계약, CHANGELOG 링크만 남긴다. 릴리스 노트 절은 없고, 전체는 200줄 이하다. 시작 안내 아래에 기여자용 한 줄을 둔다. `just`를 실행하면 레시피 목록이 나온다는 내용이다.
- 저장소 루트에 CHANGELOG를 둔다. 최신 버전이 위에 오며, 0.8.0부터 0.31.0까지 지금 README에 있는 28개 버전이 모두 항목을 가진다.
- 버전 항목 하나는 다음으로 이루어진다. 순서도 이대로다.
  - 버전과 날짜.
  - 그 릴리스를 한두 문장으로 요약한 문장.
  - Breaking, Added, Changed, Fixed, Removed 중 해당하는 소절.
  - 필요할 때만 Upgrading 소절. 사용자가 할 일을 순서대로 적는다.
- 항목 한 줄은 사용자가 보는 변화 하나다. 명령, 옵션, 출력 필드, 종료 코드로 말한다. 변경 slug, 내부 모듈, 리뷰 라운드, 측정 수치, 구현 이유는 쓰지 않는다. 언어는 README와 같은 영어다.
- 옛 노트에서 사용자가 해야 하거나 알아야 하는 것은 하나도 빠지지 않는다. 업그레이드 단계, 깨지는 변경, 바뀐 철자, 바뀐 JSON 필드와 스키마 버전이 여기에 해당한다. 그 밖의 서술은 줄이거나 뺀다.
- CHANGELOG 머리에 한 줄을 둔다. 옛 노트 전문을 읽으려면 이 변경 직전 커밋의 README를 `git show`로 보라고 적는다.
- 생성되는 바뀐 철자 표 두 개는 CHANGELOG의 해당 버전 Upgrading 소절로 옮긴다. 0.27→0.28 표와 0.30→0.31 표다. 생성기와 drift 검사는 CHANGELOG를 대상으로 하며, 표 내용은 바뀌지 않는다.
- 다음 셋은 README 대신 CHANGELOG를 본다.
  - README의 릴리스 문구를 읽던 테스트.
  - README 링크 검사.
  - "README의 표"나 "README의 Upgrading 목록"을 가리키던 문서와 소스 주석. 웹사이트의 영어와 한국어 문서, 설계 문서, 소스 주석이 해당한다.
- 릴리스 워크플로 안전 검사는 루트에 CHANGELOG와 justfile을 허용한다.
- justfile 레시피는 CI와 같은 명령을 같은 옵션으로 돈다. 기본 레시피는 목록을 보여 준다. 레시피는 다음과 같다.
  - 빌드와 설치.
  - 워크스페이스 테스트.
  - CI의 clippy 세 줄.
  - canon 자체 gate: inventory sync 뒤 gate check.
  - 생성 문서 다시 쓰기.
  - conformance 기대값 다시 쓰기.
  - 릴리스 안전 검사와 그 테스트.
  - 런처 bun 테스트, platformer 테스트, 대시보드 빌드.
  - 맨페이지와 벤치.
  - live tier: docker compose를 올리고 테스트한 뒤 내린다.
  - 묶음 레시피: docker 없이 도는 CI 잡 전부.
- 빌드 출력 경로는 cargo 규칙을 따른다. 사용자가 target 경로 환경 변수를 정해 두었으면 그 경로를 쓰고, gate 레시피가 실행하는 바이너리도 같은 경로에서 찾는다. 개인 머신의 경로는 justfile에 적지 않는다.

## Checks

- ==**`cargo test --workspace`가 통과한다.**== 생성 문서 drift, 문서 lint, 링크 검사, 릴리스 문구를 읽는 테스트가 여기에 포함된다. 같은 커밋에서 clippy, 릴리스 안전 검사, 그 검사의 테스트도 통과한다.
- `just --list`가 위 레시피를 모두 보여 준다. docker가 필요한 live 레시피를 뺀 레시피는 로컬에서 한 번씩 돌려 통과를 확인하고, 그 결과를 evidence에 남긴다. live 레시피는 docker가 있으면 돌리고, 없으면 돌리지 못했다고 적는다.
- README가 200줄 이하이고 릴리스 노트 절이 없다.
- 리뷰어는 CHANGELOG에서 버전 다섯 개를 골라 옛 노트와 대조한다. 0.28.0과 0.31.0은 반드시 포함한다. 업그레이드 단계, 깨지는 변경, 바뀐 철자, 바뀐 필드 중 빠진 것이 없는지 확인하고, 항목이 slug나 내부 모듈 없이 읽히는지도 확인한다.
- 이 변경은 테스트, 생성기, 스크립트, justfile을 바꾸므로 코드 변경으로 센다. 그래서 출시된 gate-trust-spine을 다시 열고, `--all-scenarios` evidence를 기록한 뒤 출시한다. 변경 단위 리뷰는 다른 세션의 reviewer가 한다.

## Out of scope

- canon 동작 변경, 버전 올리기, 릴리스.
- CI 워크플로가 just를 쓰게 바꾸는 일. CI는 지금 명령을 그대로 쓴다.
- rustfmt 검사 단계 추가.
- 웹사이트에 changelog 페이지를 두는 일, 한국어 changelog.
- 설계 문서, 리서치 문서, 아키텍처 문서의 정리.

## Questions and assumptions

- CHANGELOG는 영어로 쓴다. README, 스킬 가이드, 영어 웹사이트와 언어를 맞추기 위해서다.
- 날짜는 버전 태그의 날짜를 쓴다. 태그가 없는 버전(0.19, 0.20 등)은 버전을 올린 커밋의 날짜를 쓴다.
- 이 chore는 gate-trust-spine에 adopt한다. 0.30과 0.31의 CI chore가 같은 subject에 붙었던 선례를 따른 것이다.
