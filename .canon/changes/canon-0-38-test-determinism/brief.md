# 두 시험이 우연과 호출자 환경에 기대지 않는다

Source: 0.36과 0.37 릴리스 중 관찰한 실패 보고, 시험 `every_spec_example_document_writes_what_its_flags_write`와 `authoring_init_93`, 커밋 314ab1f10(같은 종류의 앞선 수정)

## Intent

시험 하나는 모든 쓰기 명령의 예시 문서가 플래그와 같은 기록을 쓰는지 묻는다. 기록 파일 이름은 끝에 내용 다이제스트 8자리를 달고, 시험은 이름을 비교하기 전에 이 다이제스트를 가린다. 가림 규칙은 숫자가 하나라도 든 다이제스트만 가린다. a부터 f까지의 글자로만 된 다이제스트는 가려지지 않아 두 실행의 이름이 달라진다. 한 번 돌릴 때 확률은 3~4%로 어림된다.

다른 시험 하나는 제공자를 하나도 고르지 않은 `canon init` 출력의 마지막 줄을 단언한다. 호출한 셸에 구현자, 리뷰어, 오케스트레이터 역할이 선언되어 있으면 마지막 줄이 달라져 실패한다. 역할 변수를 비우지 않고 canon을 실행하는 시험 파일이 65개다.

## Category

refactor

## Invariants

- canon의 동작, 출력, 종료 값, 기록 형식, 생성 문서는 바뀌지 않는다. 바뀌는 것은 시험 코드뿐이다.
- ==**가림은 가리는 값을 늘릴 뿐 비교를 느슨하게 하지 않는다. 두 실행이 다른 내용을 쓰면 시험은 지금처럼 실패한다.**==
- 시험이 확인하는 규칙과 시나리오 문장은 그대로다.
- 시험은 호출자의 역할과 행위자 환경 변수를 물려받지 않고, 시험이 정한 값만 쓴다.

## Checks

- 8자리가 모두 a부터 f인 다이제스트(`cfcaaadc`, `abcdefab`)가 파일 이름과 본문에서 가려지는지 보이는 표 시험이 있다.
- 같은 표 시험에 두 실행이 다른 내용을 쓰는 입력이 있고, 비교가 그것을 실패로 낸다.
- canon-cli 시험 전체를 역할을 비운 채, 구현자 역할과 행위자를 선언한 채, 알 수 없는 역할 값을 둔 채 각각 돌려 결과가 같다.
- ==**장애를 일으키던 시험 둘이 세 환경에서 모두 통과하고 canon-cli 시험 전체의 통과 수가 바뀌지 않는다.**==
- 변경 뒤 주제의 시나리오 전체를 같은 시험 보고서로 다시 묶는다.

## Out of scope

- canon 본체 코드와 출력.
- 시험의 실행 시간과 부하 아래의 타임아웃.
- 관찰되지 않은 다른 불안정 시험.
- 시험 실행기 설정을 바꿔 환경을 지우는 방법.
