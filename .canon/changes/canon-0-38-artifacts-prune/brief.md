# canon artifacts prune은 어떤 기록도 더는 쓰지 않는 블롭을 지운다

Source: canon 이슈 #138의 첫 항목(GC)과 소유자 댓글, `canon artifacts verify`와 `canon artifacts move`, 이 저장소의 증거 저장소를 0.37.0 바이너리와 파일로 잰 값

## Intent

증거 블롭 저장소는 늘기만 한다. 이 저장소에는 블롭 174개, 62,647,897바이트(59.7 MiB)가 있다. 게이트와 `artifacts verify`가 읽는 기록, 곧 작업별과 (프로젝트, 시나리오)별 최신 증거와 현재 리뷰가 묶은 블롭은 9개, 3,712,209바이트다. 나머지 165개, 58,935,688바이트(94%)는 어떤 기록도 묶지 않는다. 보고서를 실행마다 새로 쓰면 블롭이 실행마다 하나 늘고, 지우는 명령이 없다.

## Desired outcome

- `canon artifacts prune`은 기본이 미리보기다. 지울 블롭과 남길 블롭의 수와 바이트, 남기는 이유를 말하고 아무것도 쓰지 않는다.
- ==**`--commit`과 미리보기가 낸 `--plan-digest`를 함께 주면 그 목록의 블롭만 지운다.**==
- 게이트와 `artifacts verify`가 읽는 블롭, 승격 전 기록이 묶은 블롭, `--keep-days`로 고른 기간의 기록이 묶은 블롭은 남는다.
- 지운 뒤 `artifacts verify`와 `gate check`의 답은 지우기 전과 같다.
- 설정한 저장소가 로컬이든 객체 저장소 계층이든 같은 규칙이다.
- 지운 로컬 블롭이 git 기록에 남는다는 말이 안내문에 있다.

## User flow

1. F1 오케스트레이터는 `canon artifacts prune`을 인자 없이 돌린다 → 미리보기가 나온다 → 지울 양과 남길 이유를 읽는다.
2. F2 오케스트레이터는 미리보기가 낸 계획 다이제스트로 `--commit`을 돌린다 → 목록의 블롭이 지워진다 → `canon artifacts verify`가 통과한다.
3. F3 오케스트레이터는 `--keep-days`를 준다 → 그 기간의 기록이 묶은 블롭이 남는다 → 지울 양이 줄어든다.
4. F4 오케스트레이터는 객체 저장소 계층이 설정된 저장소에서 돌린다 → 같은 규칙으로 계층의 객체를 지운다 → 로컬 사본과 계층이 어긋나지 않는다.
5. F5 오케스트레이터는 미리보기 뒤 저장소가 바뀐 채 `--commit`을 돌린다 → 거절된다 → ==**아무것도 지워지지 않고 미리보기를 다시 돌리라는 안내를 받는다.**==
6. F6 사람은 안내문과 CHANGELOG를 읽는다 → 지운 블롭이 git 기록에 남는다는 말과 새 명령이 있다 → 기록 축소는 저장소 주인이 정한다.

## Step detail

### F1 미리보기

- 남기는 블롭은 이유를 단다. 최신 증거, 현재 리뷰, 승격 전 기록, 기간 안의 기록이 있다. 한 블롭이 여럿에 해당하면 이유를 모두 든다.
- 지울 블롭의 목록은 한 번에 최대 건수로 자르고 총수와 총 바이트는 전체를 말한다. 목록은 페이지로 이어 읽는다.
- 종료 값은 0이고 `committed`는 거짓이며 `meta.next`의 첫 항목이 그대로 돌릴 수 있는 `--commit` 명령이다.
- 지울 것이 없으면 그렇게 말하고 `--commit` 명령을 내지 않는다.

### F2 실행

- ==**실행은 계획 다이제스트가 지금 계산한 것과 같을 때만 한다.**== 다이제스트는 지울 블롭 목록과 읽은 상태를 덮는다.
- 지우는 동안 저장소 쓰기 잠금을 잡는다. 중간에 끊겨도 다시 돌리면 남은 것만 지운다.
- 기록을 읽지 못하거나 잠금을 못 잡으면 아무것도 지우지 않고 거절한다. 남길 목록을 확신하지 못하면 지우지 않는다.
- 지운 블롭과 남은 블롭의 수를 말한다. 로컬 사본은 작업 트리에서 사라지므로 커밋이 필요하다고 말한다.

### F3 기간

- `--keep-days`는 1 이상의 정수다. 기록 시각이 그 일수 안인 증거와 리뷰가 묶은 블롭은 남는다. 옵션이 없으면 기간 보존은 없다.

### F4 객체 저장소 계층

- 설정한 저장소가 계층이면 계층의 객체를 같은 규칙으로 지운다. 계층에서 지우는 일은 되돌릴 수 없으므로 미리보기가 그 사실과 객체 수를 말한다.
- 계층의 객체 목록 읽기나 삭제가 실패하면 거절하고, 지운 만큼은 말한다. 다시 돌리면 이어서 지운다.

### F5 낡은 계획

- 미리보기 뒤 새 증거가 블롭을 묶었거나 기록이 바뀌었으면 다이제스트가 어긋나 종료 값 2의 거절이 된다. 아무것도 지우지 않는다.
- 다이제스트 없이 `--commit`만 주면 지금의 파괴 명령처럼 거절한다.

### F6 안내

- 스킬 안내문과 CHANGELOG의 Added가 새 명령을 말한다. 지운 로컬 블롭이 git 기록에 남고 기록 축소는 저장소 주인이 따로 정한다는 말을 담는다.
- 명령은 오케스트레이터 역할의 것이다. 다른 `artifacts` 명령과 같다.

## Acceptance

- F1:
  - 블롭 셋(최신 증거가 묶은 하나, 어떤 기록도 묶지 않은 둘)의 저장소에서 미리보기가 지울 둘과 남길 하나를 말하고 파일은 그대로다.
  - 실패 경로: 지울 것이 없는 저장소의 미리보기는 `--commit` 명령을 내지 않는다.
- F2:
  - 계획 다이제스트로 실행하면 어떤 기록도 묶지 않은 블롭 둘이 사라지고 `artifacts verify`와 `gate check`의 답이 같다.
  - 실패 경로: ==**기록을 읽지 못하는 저장소에서는 아무것도 지우지 않고 거절한다.**==
- F3:
  - 기간 안의 기록이 묶은 블롭은 `--keep-days`를 주면 남고 주지 않으면 지워진다.
  - 실패 경로: `--keep-days 0`과 음수는 종료 값 2로 거절된다.
- F4:
  - 객체 저장소 계층이 설정된 저장소에서 계층의 불필요한 객체가 지워지고 남길 객체는 `verify --full`을 통과한다.
  - 실패 경로: 계층이 삭제를 거부하면 거절하고 남길 객체를 지우지 않는다.
- F5:
  - 미리보기 뒤 증거를 하나 더 묶고 `--commit`을 돌리면 거절되고 블롭이 그대로다.
  - 실패 경로: 다이제스트 없는 `--commit`은 거절된다.
- F6:
  - 안내문과 CHANGELOG에 항목이 있다.
  - 실패 경로: 항목이 없으면 릴리스 확인 시험이 실패한다.
- 생성 문서 drift 시험과 `just atip-deep`이 통과한다.

## Questions and assumptions

- 결정: 이번 변경은 지우기만 한다. 압축, 미디어 변환, 이미지와 영상용 별도 계층, 보고서의 추출본만 저장하는 일은 뒤로 미룬다. 지운 뒤 이 저장소에는 9개, 3.7MB가 남고, 블롭 174개를 zstd로 압축하면 8.3MB가 되지만 남은 9개에서 얻는 몫은 작다. git은 이미 압축한다. 변환과 별도 계층은 원본과 저장본의 다이제스트를 함께 기록하는 증거 의미의 결정이고, 이 저장소에는 이미지 블롭이 없다.
- 결정: 기본 보존은 게이트가 읽는 집합과 승격 전 기록이 묶은 블롭이다. 기간 보존은 선택이다.
- 결정: 객체 저장소 계층을 이번에 포함한다. 계층에는 삭제가 없어 새로 더한다.
- 결정: 지운 뒤 더는 최신이 아닌 옛 기록의 블롭은 다시 읽을 수 없다. 로컬 블롭은 git 기록에서 되살린다.
- 결정: 되돌릴 수 없는 삭제를 하는 명령이 생기므로 미리보기와 계획 다이제스트가 있어야 실행된다. 보존 규칙은 이 브리프가 정한다.

## Out of scope

- 블롭 압축과 읽기 형식 변경.
- 스크린샷과 영상의 변환, 별도 계층 경로 지정, 보고서 추출본 저장.
- git 기록 축소와 LFS 설정.
- 정해진 주기로 자동 실행하는 일.
