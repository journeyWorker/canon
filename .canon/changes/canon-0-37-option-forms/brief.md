# 승인 시각 옵션은 RFC 3339만, 제공자 목록 옵션은 정확한 이름만 받는다

Source: canon 0.36.0 바이너리가 받는 `--approval-at`과 `--providers`의 값을 잰 결과, RFC 3339 5.6, https://github.com/journeyWorker/atip 태그 v1.5.0 annex-domains.md V2, canon-0-37-claim-1-5, canon-0-37-option-values

## Intent

`--approval-at`은 서명에 드는 시각이다. 0.36은 앞의 공백, 한 자리 월과 일, 소문자 `t`와 `z`, 공백 구분자, 유니코드 빼기 부호의 오프셋, 날짜만 있는 값을 받는다. 같은 시각을 여러 철자로 쓸 수 있다. `--providers`는 대소문자를 가리지 않고 빈 항목과 항목 둘레의 공백을 받는다. `init`은 선언된 도메인이 없고 핸들러가 이름만 검사한다. 두 옵션이 받는 철자를 계약이 읽을 수 있는 정확한 형태로 좁힌다.

## Desired outcome

- `--approval-at`은 RFC 3339의 date-time만 받는다. 날짜만 있는 값, 앞뒤 공백, 한 자리 월과 일, 부호 붙은 연도, 공백 구분자는 거절한다.
- ==**`--approval-at`의 값은 canon이 찍지 않고 호출자가 한 번 정해 서명과 기록에 같게 쓴다.**==
- 시각 옵션 `--expiry`, `--as-of`, `--before`, `--after`, `--since`는 RFC 3339의 full-date나 date-time을 받는다.
- `--providers`는 `claude`, `codex`, `omp`, `pi`를 쉼표로 이은 값이나 `none`만 받는다. 이름이 다르거나 항목이 비었거나 둘레에 공백이 있으면 거절한다.
- `init`과 `skills`의 세 명령이 같은 규칙을 선언한다.
- 새로 거절되는 값과 옮기는 방법이 CHANGELOG에 있다.

## User flow

1. F1 서명자는 `--approval-at`으로 `evidence approval-payload`나 `strategy approval-payload`를 부른다 → RFC 3339 date-time만 받아 그 시각이 든 서명 바이트가 온다 → ==**그 바이트에 서명하고 같은 시각을 기록에 쓴다.**==
2. F2 서명자는 같은 시각으로 `evidence add`나 `strategy rollback`을 부른다 → 같은 규칙으로 읽고 서명을 검증한다 → 기록이 남는다.
3. F3 에이전트는 `--expiry`, `--as-of`, `--before`, `--after`, `--since`에 날짜나 시각을 준다 → RFC 3339 철자만 받는다 → 바른 철자로 쓴다.
4. F4 에이전트는 `init`과 `skills`의 세 명령에 `--providers`를 준다 → 정확한 이름만 받는다 → 이름을 정확히 쓴다.
5. F5 에이전트는 `canon schema`로 두 옵션의 도메인을 읽는다 → 명령마다 같은 선언이다 → 호출 전에 값을 검사한다.
6. F6 사람은 CHANGELOG를 읽는다 → 새로 거절되는 철자와 옮기는 방법이 있다 → 호출자를 고친다.

## Step detail

### F1 서명 바이트

- 받는 철자는 `YYYY-MM-DDTHH:MM:SS`, 선택적 소수부, `Z`나 `±HH:MM`이다. 월과 일과 시각은 두 자리이고 연도는 네 자리이다. RFC 3339의 문법대로 `T`와 `Z`는 소문자도 받는다.
- 거절하는 철자는 다음과 같다. 날짜만 있는 값, 앞뒤 공백, 한 자리 월과 일, 부호 붙은 연도가 있다. `T` 대신 공백, 유니코드 빼기 부호 오프셋, 초가 없는 시각, 오프셋 없는 시각도 거절한다.
- 존재하지 않는 날짜와 시각(`2026-02-30`, 25시)은 지금처럼 거절한다.
- 서명 바이트는 시각을 UTC 나노초로 정규화해서 담는다. 오프셋이 다른 같은 순간은 같은 바이트이다.
- ==**두 `approval-payload`는 시계를 읽지 않고 같은 인자에 같은 바이트를 낸다.**== 이 성질은 그대로다.

### F2 기록

- `evidence add`와 `strategy rollback`은 F1과 같은 규칙으로 `--approval-at`을 읽는다. 시각이 서명한 값과 다르면 서명 검증이 거절한다.
- `evidence add`의 승인 옵션 넷(`--approver`, `--approval-role`, `--signature-file`, `--approval-at`)이 함께 와야 하는 규칙은 그대로다.

### F3 날짜 옵션

- 날짜는 `YYYY-MM-DD`이고 월과 일이 두 자리, 연도가 네 자리이다. 앞뒤 공백과 부호 붙은 연도는 거절한다. 날짜만 있는 값은 그날 UTC 0시이다.
- 시각은 F1의 date-time 철자이다.
- 날짜가 달력에 없으면 지금처럼 거절한다. `--after`가 `--before`보다 늦은 쌍을 거절하는 검사도 그대로다.

### F4 제공자 목록

- 받는 값은 `none`이거나 `claude`, `codex`, `omp`, `pi` 중 하나 이상을 쉼표 하나로 이은 것이다. 이름은 소문자이다.
- 거절하는 값: `Claude`, `NONE`, `claude,,pi`, `claude,`, ` claude`, `claude, pi`, 빈 문자열, `none,claude`, 모르는 이름. 0.36에서 빈 문자열은 제공자 없음이었다.
- `init`은 도메인을 선언하고 거절은 `INIT_ARGUMENT_INVALID`이다. `skills`의 세 명령은 `SKILLS_ARGUMENT_INVALID`이다. 거절하면 아무것도 쓰지 않는다.
- 같은 이름을 두 번 적은 값은 이 변경이 새로 거절하지 않는다.

### F5 선언

- 도메인은 1.5 어휘로 쓴다. 제공자 목록은 이름과 쉼표만으로 정해지는 패턴이고, 시각은 숫자와 구분자만으로 정해지는 패턴이다. 값표(안쪽 값, 바깥 값)를 실제 파서에 돌려 증명한다.
- `--approval-at` 네 곳의 선언이 같고, 날짜 옵션 다섯 곳의 선언이 같다. 도움말은 새 철자를 말한다.

### F6 변경 기록

- CHANGELOG의 Breaking 항목에 옵션, 0.36이 받던 철자, 0.37의 처리를 표로 싣는다. 옮기는 방법은 철자마다 적는다. 날짜만 쓰던 `--approval-at`은 시각까지 적어 서명을 다시 만든다.

## Acceptance

- F1:
  - `2030-01-01T10:00:00Z`와 `2030-01-01T10:00:00+09:00`을 받고 UTC로 정규화한 바이트가 같은 순간에서 같다.
  - 실패 경로: `2030-01-01`, ` 2030-1-1T10:00:00Z`, `2030-01-01 10:00:00Z`는 종료 값 2로 거절되고 바이트가 stdout에 나오지 않는다.
- F2:
  - 서명한 시각과 같은 `--approval-at`으로 `evidence add`가 승인 기록을 남기고 `strategy rollback`이 롤백을 남긴다.
  - 실패 경로: 다른 시각이나 거절되는 철자면 아무것도 기록하지 않는다.
- F3:
  - `--expiry 2030-01-01`과 `--since 2030-01-01T00:00:00Z`를 받는다.
  - 실패 경로: `--expiry 2030-1-1`과 `--as-of " 2030-01-01"`은 거절되고 기록이 없다.
- F4:
  - `claude`, `claude,omp`, `none`을 네 명령이 받는다.
  - 실패 경로: ==**`Claude`, `claude,,pi`, `claude, pi`, 빈 문자열, `none,claude`를 네 명령이 모두 거절하고 아무것도 쓰지 않는다.**==
- F5:
  - 같은 옵션은 명령마다 같은 도메인이고 값표 전체가 파서와 맞는다.
  - 실패 경로: 한 명령이 다른 도메인을 선언하면 시험이 실패한다.
- F6:
  - CHANGELOG 표가 새로 거절되는 철자마다 한 행을 갖는다.
  - 실패 경로: 표에 빠진 거절이 있으면 릴리스 확인 시험이 실패한다.
- `just atip-deep`이 1.5로 통과하고 생성 문서 drift 시험이 통과한다.

## Questions and assumptions

- 결정: canon이 승인 시각을 직접 찍는 설계는 택하지 않는다. 이유 셋이다. `strategy rollback`에는 서명할 바이트를 내는 명령이 없어서 새 명령이 필요하다. SSH 서명 파일은 서명한 바이트를 담지 않아서 시각을 읽으려면 바이트 파일을 받는 새 옵션이 필요하고 표준 입력으로 서명하면 그 파일이 없다. 두 `approval-payload`는 같은 인자에 같은 바이트를 낸다고 출하된 시나리오가 고정하고, 시각을 찍으면 재실행이 서명한 바이트와 다른 바이트를 낸다. 사람이 이 결정을 뒤집으면 별도 변경으로 계획한다.
- 가정: 날짜 옵션 다섯 곳도 같은 철자 규칙으로 좁힌다. 지금은 모든 시각 옵션이 앞 공백, 한 자리 월과 일, 부호 붙은 연도를 받는다. `--approval-at`만 좁히려면 사람이 알려 준다.
- 가정: RFC 3339 문법대로 `T`와 `Z`의 소문자를 받는다. 대문자만 받으려면 사람이 알려 준다.
- 가정: 같은 이름을 두 번 적은 제공자 목록은 받는다. 거절하려면 사람이 알려 준다.
- 가정: `canon.yaml`의 `skills.providers` 설정 값은 옵션이 아니어서 이 변경 밖이다.
- 정책 질문: 이전에 받던 철자가 거절되므로 호출자에게 깨지는 변경이다. 서명 자동화가 날짜만 쓰던 `--approval-at`을 서명하고 있다면 서명을 다시 만들어야 한다. 사람이 이 거절 목록을 승인한다.

## Out of scope

- canon이 승인 시각을 찍는 설계와 `strategy rollback`용 서명 바이트 명령.
- 시각 옵션이 아닌 옵션의 값 규칙(canon-0-37-option-values).
- 설정 파일의 제공자 목록.
- 표준 시간대 이름이나 달력 밖의 시각 표기.
