# Design System: canon

## Overview

**Creative North Star: "The Checks Panel"**

canon is drawn as the screen its audience already trusts: a pull request whose checks block the merge. The landing page and the docs share one GitHub-dark ground, panels with 1px edges, rows divided by horizontal rules, and state colours that always arrive with a word. Nothing is decorated; every surface is a panel, a row, a log, or a table, and the composition borrows its authority from the tooling engineers already read every day.

Density is that of a code-review screen, not a marketing page. The first viewport is a fixed composition (a three-line statement and an install command on the left, the pull-request panel on the right) scaled as one frame; everything after it is fluid sections of panels and tables at a comfortable reading measure. Emphasis comes from weight and from the single red verdict, never from a brand colour: the system has no accent hue of its own, only the colours of check states.

The docs (Starlight) are the same world in reading mode: the same ground, panel, rule, and text values mapped onto Starlight's custom properties, code frames styled as the inset log field, and a readable GitHub-light theme kept available. The rejected Grid Manual world (warm paper, orange signal, twelve vertical column hairlines) does not survive anywhere.

**Key Characteristics:**
- GitHub-dark ground with tonal panels a few steps lighter; depth by tone and 1px edges, not shadow.
- Horizontal row dividers and panel edges only; no vertical grid hairlines.
- Check-state colours (pass, fail, pending, waiting) are the only hues, and each is paired with a word or an icon.
- Mona Sans bold for statements and UI; Geist Mono for commands, logs, and code.
- One orchestrated motion: the checks resolve, the gate log arrives, the Merge blocked badge answers once.
- The first viewport scales as a single 1774px frame down to 1100px, then stacks.

## Colors

A cool, near-black GitHub-dark neutral ramp carrying a small set of check-state colours that mean exactly what they mean on a pull request.

### Primary
- **Gate Red** (fail): the failing check's dot, the gate event's badge in the timeline, the red ring in the badge pulse, and danger asides in the docs. It is the one verdict on the first viewport.
- **Blocked Fill** (fail-fill): the solid fill of the Merge blocked badge, a deeper red so white text on it holds contrast.
- **Passed Green** (pass): passed check dots, "Yes" capability cells, the check marks in what canon proves, tip asides, and the Copy button's copied state.
- **Pending Amber** (pending): "Partial" capability cells, caution asides, and the ring a check dot resolves from.
- **Waiting Grey** (wait): the dot of a check that has not run (deploy).
- **Red Wash / Amber Wash** (fail-low, pending-low): the tinted grounds of danger and caution asides in the docs.

### Neutral
- **Ground** (ground): page background on both landing and docs; also the browser theme colour.
- **Log Inset** (inset): the sunken field of the expanded check log and the terminal blocks, one step from the ground.
- **Panel** (panel): every landing panel surface: command field, PR panel, comparison scroll region, proves/doesn't panels, docs file list.
- **Raise** and **Raise Hover** (raise, raise-hover): hover fills for docs-list rows and the Copy button.
- **Canon Row Tint** (canon-row): the background of the canon row in the comparison table (also Starlight's low blue/purple).
- **Docs Panel** (docs-panel) and **Docs Inset** (docs-inset): the docs' table header, aside, card, and search ground; the code-block and terminal background in Expressive Code (also its tab bar and title bar use docs-panel).
- **Current Page** (docs-current): the fill behind the current sidebar link.
- **Shade** (shade): the near-black base of every shadow and overlay (sticky column edge, Starlight modal backdrop).
- **Border** (border) and **Soft Border** (border-soft): panel edges and header rules, and the row dividers inside panels. Inside the PR panel these are re-scoped to **PR Border** and **PR Soft Border** (pr-border, pr-border-soft) to match the approved comp.
- **Text** (text): primary landing text. **Bright Text** (text-bright): docs headings, title, and emphasis. **Soft Text** (text-soft): docs body copy and the landing nav links. **Log Text** (log-text): text inside the check log and terminal blocks.
- **Secondary Text** (text-2): leads, descriptions, notes, column heads, "No" and "Not documented" cells. **Tertiary Text** (text-3): the dimmest legible grey.
- **Link Underline** (link-line): the 1px underline colour under docs links before hover.

### Docs Light Theme
The landing is dark only; the docs keep GitHub's light palette selectable and readable. **Light Ground** (light-ground), **Light Panel** (light-panel, also the code background), **Light Inline Code** (light-inline-code), **Light Border** and **Light Soft Border** (light-border, light-border-soft), **Light Text** (light-text) with **Light Secondary** and **Light Tertiary** text (light-text-2, light-text-3), and the light check states **Light Pass**, **Light Fail**, **Light Pending** (light-pass, light-fail, light-pending) with their aside washes (light-fail-low, light-pending-low). Expressive Code switches to github-light-default in this theme.

### Named Rules
**The Word Beside the Colour Rule.** A state colour never stands alone. Every dot, ring, or tint sits beside its word ("passed", "waiting", "Merge blocked", "Yes", "Partial", "No", "Not documented") or a distinct icon shape, so the panel reads the same in greyscale.

**The No Brand Accent Rule.** There is no accent hue. Links, focus, and the current page use the text and grey steps; red, green, and amber appear only where they report a check state.

**The Tint Not Stripe Rule.** A highlighted row (the canon row in the comparison) is a full-row background tint. Never a coloured side stripe or a thick left border.

## Typography

**Display Font:** Mona Sans Variable (with Noto Sans KR Variable, Apple SD Gothic Neo, Malgun Gothic, system-ui)
**Body Font:** Mona Sans Variable (same stack)
**Label/Mono Font:** Geist Mono Variable (with ui-monospace, SFMono-Regular, Menlo, Noto Sans KR Variable)

**Character:** Mona Sans at 700 makes the statements feel like GitHub's own interface speaking plainly; Geist Mono carries anything a terminal would print. Korean falls back to Noto Sans KR in both stacks, and Korean docs prose uses keep-all line breaking.

### Hierarchy
- **Display** (700, scaled 88 units on a 92-unit line, -0.03em): the three-line hero statement only. Stacked below 1100px it becomes the fluid `display-stacked` role.
- **Headline** (700, clamp 32px–50px, 1.08, -0.025em, balanced wrap): section headings.
- **Title** (650, 21px, 1.25): timeline event names. **Subtitle** (650, 20px, 1.3): sub-headings inside a section.
- **Lead** (400, 18px, 1.6, max 62ch, secondary text): the sentence under a section heading.
- **Body** (400, 17px, 1.6, max 62ch): landing prose; docs prose runs at Starlight's size with a 1.7 line height.
- **Row** (650, 16px, 1.3): the tool names heading comparison rows and the stacked nav. **Row Detail** (15.5px, 1.5): docs-list descriptions and stacked check rows. **Small** (15px): footer, flow path, stacked command and badge text.
- **Label** (600, 14px, 1.3): capability-cell state words and table body. **Column Head** (600, 13.5px, 1.35, secondary text): comparison column headings.
- **Wordmark** (700, -0.03em): scaled 43 units in the hero header, 28px stacked (`wordmark-stacked`), 24px (1.5rem) in the landing footer and the docs header (`wordmark-small`).
- **Command / Log / Code** (Geist Mono 400): the install command (scaled 26 units), the check log (scaled 18.5 units on 29, 12.5px stacked), and terminal and docs code (14px, 1.7).

### Named Rules
**The Weight Not Size Rule.** Hierarchy inside panels is carried by weight (600–700 for names, 400 for summaries) and by text grey, not by extra sizes. Headings use 650 or 700; nothing uses a light weight.

**The Mono Means Machine Rule.** Geist Mono is reserved for what a machine reads or prints: commands, logs, paths, code. Never for headings or decoration.

## Layout

The first viewport is one frame laid out in a single unit, `--u = min(1px, 100vw / 1774)`: a 1774px-wide composition that scales down proportionally with the viewport and never above 1:1. The header is 110 units tall; the hero is a two-column grid (771 + 824 units, 69-unit gap, minimum height 777 units) with the statement and command field on the left and the PR panel on the right. Every hero size, gap, radius, and stroke is expressed in units so the composition keeps the approved comp's proportions from 1774px down to 1100px.

At 1099px and below the frame stacks: one column, the gutter becomes `gutter-stacked`, and hero values switch to fixed pixel sizes. At 560px and below the Copy label collapses to its icon (the label stays for screen readers), check summaries wrap under the check name, and the footer becomes a single column.

After the first viewport, sections are fluid: a 1774px maximum width with the page gutter, `section` padding above each, and `block` spacing between a heading and its content. The flow section is a 5:7 two-column grid with a sticky heading; the comparison, quick start, proves/doesn't, and docs list are full-measure panels. Prose holds to about 62ch.

**The Rows Not Columns Rule.** Lines run horizontally: panel edges and the dividers between rows. There are no vertical grid hairlines or column rules anywhere, including inside tables. The only vertical strokes are the 2px thread joining timeline badges (beside the text, never through it) and the 1px divider inside the command field before Copy.

**The Real Table Rule.** The comparison is a real `<table>` at every width: inside a labelled, focusable scroll region, with a minimum width (1220px, 1100px stacked) and a sticky first column of tool names. It never reflows into cards.

## Elevation & Depth

The system is flat. Depth is tonal (ground, then inset or panel, then raise) and every panel is bounded by a 1px edge. Shadows appear only where an edge needs to read over moving content or as a state answer.

### Shadow Vocabulary
- **Sticky column edge** (`box-shadow: 10px 0 14px -10px rgba(1, 4, 9, 0.9)`): the comparison's sticky first column when stacked, so scrolled cells pass beneath it.
- **Badge pulse** (`box-shadow: 0 0 0 0 → 0 0 0 calc(12 * var(--u))` in Gate Red fading from 0.55 to 0 alpha): the Merge blocked badge's single answer during the opening motion.
- **Docs overlays** (`--sl-shadow-sm/md/lg`: `0 1px 2px`, `0 8px 24px`, `0 16px 40px` on the Shade base at 0.4–0.6 alpha): Starlight's search dialog and menus only. Docs cards, pagination links, and code frames carry no shadow.

### Named Rules
**The Edge Before Shadow Rule.** A surface separates from the ground with a tone step and a 1px border. A shadow is never the primary separator.

## Shapes

Corners are gently rounded and consistent: the small radius (sm) for controls, inline chips, the docs search field, and sidebar links; the medium radius (md) for every panel, table, aside, card, terminal, and Expressive Code frame. In the scaled first viewport the radii scale too: the log inset (hero-log), the command field, Copy button, and Merge blocked badge (hero-field), and the PR panel (hero-panel). Status dots and timeline badges are full circles; the focus ring and docs kbd use the extra-small radius; threads are 2px wide with 1px rounding.

Panels clip their contents (`overflow: hidden`) so row hovers and the first header cell follow the corner. Tables use separated borders with zero spacing so the outer radius holds.

## Components

### Command Field and Copy Button
The primary action: the install command printed as a terminal line inside a panel field.
- **Shape:** the hero-field radius on the field and the button; the field is a two-column grid (command, then Copy) with a 1px vertical divider owned by the field.
- **Field:** Panel ground, a 1px border a step lighter than the panel edge, Log Text in Geist Mono with a `$ ` prompt that is hidden from assistive tech. The command scrolls horizontally rather than wrapping.
- **Copy button:** Mona Sans 500 with a stroked copy icon, a near-raise fill with its own 1px border and a 1px outer ring; hover moves to Raise Hover with a lighter border (160ms ease-out). On copy the label reads the localized "Copied", the text and border turn Passed Green, and a live region announces it; it resets after 1.6s.
- **Stacked:** 60px tall field, 40px button; at 560px and below the label is visually hidden and the icon remains.

### PR Panel
The hero's signature: a pull request `agent/feat-cart → main` with four checks, merge blocked.
- **Container:** Panel ground, 1px edge, hero-panel radius, clipped; PR Border and PR Soft Border re-scope the dividers inside.
- **Branch line:** Mona Sans 650 with a stroked arrow icon between head and base, a 1px rule below.
- **Merge blocked badge:** Blocked Fill with white 600 text, hero-field radius; the word is the state.
- **Check rows:** a status dot (Passed Green, Gate Red, or Waiting Grey), the check name in 600, an em dash, and the summary in secondary grey; a chevron at the end. Rows are separated by a 1px rule. Only the canon gate row is a real `<details>` that toggles; its hover is a 3% text-tone wash and its chevron rotates 180° when open. The other chevrons are markers only.
- **Expanded log:** an inset well inside the row (Log Inset ground, soft 1px border, hero-log radius), Geist Mono log lines with hanging indent, ending in `exit 1`.

### Timeline Item
The loop rendered as a pull-request timeline of six events.
- **Badge:** a 40px circle on Panel with a 1px border and a 16px stroked icon (1.4 stroke) in secondary grey. The gate event's badge turns Gate Red with a red-tinted edge and ground.
- **Thread:** a 2px Soft Border line joining one badge to the next, rounded 1px, beside the text.
- **Body:** Title-role name linking its doc (underline on hover), then secondary-grey lines at 62ch.

### Capability-Matrix Cell
One tool × capability judgement in the comparison table.
- **Container:** the table sits in a Panel scroll region with a 1px edge and the md radius; rows divide with Soft Border; the header row uses the Border tone below it.
- **Cell:** a 16px circle icon plus the state word in Label type: check and Passed Green for "Yes", half-filled circle and Pending Amber for "Partial", cross and secondary grey for "No", dashed circle and secondary grey for "Not documented". Under it a note linked to the primary source, with a dotted underline that turns solid on hover; the source name is also given to screen readers.
- **canon row:** tinted with the Canon Row Tint across every cell including the sticky header cell.

### Terminal Panel
The 60-second demo and the any-repo commands as run logs.
- **Style:** Log Inset ground, 1px Border, md radius, 20px × 22px padding, Geist Mono 14px at 1.7 in Log Text; lines never wrap and the panel scrolls horizontally. Shell comments are secondary grey.

### Check-Summary Panel
Two panels side by side: what canon proves and what it does not.
- **Style:** Panel ground, 1px Border, md radius, clipped; a lead line in 650 under a 1px rule, then rows separated by Soft Border at 14px × 22px.
- **Icons:** a stroked check in Passed Green for proven items; a slashed circle in secondary grey for what is not proven (with item text one step dimmer). Stacks to one column below 1100px.

### Docs File List
The docs index as a repository file list.
- **Style:** Panel ground, 1px Border, md radius; each row is a link with the title (650, 17px), the description (Row Detail, secondary grey), and a chevron icon, at 16px × 22px. Rows divide with Soft Border.
- **Hover:** the row fills with Raise (140ms ease-out) and the title underlines.
- **Stacked:** the description drops under the title; the chevron spans both lines.

### Navigation
- **Landing header:** wordmark at top left, nav (Docs, CLI, Concepts, GitHub) at top right in Soft Text, no underline at rest; hover turns Text with a 1px underline. Sizes scale with the frame, then 16px stacked and 15px at 560px.
- **Docs header:** a 1px Border rule below; the wordmark site title at 700; the search field on Docs Panel with a 1px edge and sm radius, hover lifting the edge and text.
- **Docs sidebar:** links with the sm radius; the current page on Current Page fill in Bright Text at 600; group labels at 650. No vertical rule between the sidebar or table of contents and the content.

### Docs Aside, Table, and Code Frames
- **Aside:** a bordered panel (Docs Panel ground, 1px Border, md radius); the state lives in the title colour and word (note in Bright Text, tip in Passed Green). Caution and danger add their wash ground and a border mixed 45% toward their state colour.
- **Table:** separated borders with zero spacing, a 1px Border edge, md radius; the header row on Docs Panel at 650; rows divide with Soft Border only; no zebra striping; first-column inline code never wraps.
- **Headings:** h2 opens a section under a Soft Border rule, as a README does.
- **Code frames:** Expressive Code with github-dark-default and github-light-default, the md radius, a 1px Border edge, Docs Inset ground, Geist Mono at 0.875rem on 1.7, no frame shadow, no tab indicator, no title-bar dots; untitled terminal frames drop their header entirely.

## Do's and Don'ts

### Do:
- **Do** draw every new surface from the pull-request vocabulary: panels with a 1px edge, rows divided by horizontal rules, logs in an inset well.
- **Do** pair every state colour with its word or a distinct icon shape (The Word Beside the Colour Rule).
- **Do** keep the comparison a real `<table>` in a labelled scroll region with a sticky first column at every width.
- **Do** express first-viewport sizes in `--u` units so the composition scales as one frame down to 1100px, and stack at 1099px and below.
- **Do** keep motion to the one orchestrated sequence (checks resolve on 300ms steps with a 520ms ease-out-expo pop, the gate log arrives, the badge pulses once) and only under `prefers-reduced-motion: no-preference`; every word is visible from the first frame.
- **Do** mirror landing tokens into Starlight through its custom properties, and keep the docs light theme on GitHub's light palette.

### Don't:
- **Don't** draw vertical grid hairlines or column rules; the rejected Grid Manual world is gone (The Rows Not Columns Rule).
- **Don't** introduce a brand accent hue or use red, green, or amber for anything other than a check state.
- **Don't** mark a highlighted row with a coloured side stripe; tint the whole row.
- **Don't** reflow the comparison into cards on small screens.
- **Don't** use Geist Mono for headings or decorative labels.
- **Don't** separate surfaces with drop shadows; use a tone step and a 1px edge.
